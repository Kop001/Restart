# JARVIS

Личный ассистент на Claude API: голос, инструменты, долговременная память,
напоминания и локальная панель оператора.

Репозиторий отвечает на вопрос «как превратить Claude в Джарвиса» не текстом,
а работающим кодом.

---

## Чего не хватает языковой модели, чтобы стать Джарвисом

Сама по себе модель — это «отвечает на вопросы». Джарвис — это «слышит, делает,
помнит и не забывает напомнить». Разница складывается из четырёх слоёв, и все
четыре есть в этом репозитории:

| Слой | Что даёт | Где в коде |
|---|---|---|
| **Голос** | слушает микрофон, реагирует на имя, отвечает вслух | `jarvis/voice/` |
| **Руки** | выполняет команды, читает и пишет файлы, ищет в вебе | `jarvis/tools/` |
| **Память** | помнит владельца между запусками, а не только внутри чата | `jarvis/memory.py` |
| **Инициатива** | сам подаёт голос, когда наступил срок | `jarvis/reminders.py` |
| **Параллельность** | ведёт несколько дел сразу, не блокируя разговор | `jarvis/tasks.py` |

Плюс два слоя, без которых это опасная игрушка, а не ассистент:

- **Разрешения** — опасные действия требуют подтверждения (`jarvis/tools/context.py`);
- **Панель оператора** — видно, что он помнит, что умеет и куда уходят токены
  (`jarvis/dashboard/`).

## Быстрый старт

```bash
git clone https://github.com/Kop001/Restart-.git
cd Restart-
pip install -e .

export ANTHROPIC_API_KEY=sk-ant-...   # или `ant auth login`

jarvis doctor      # что доступно, а что нет
jarvis             # диалог в терминале
```

Голос и панель:

```bash
pip install -e '.[voice,tts]'   # микрофон + faster-whisper + оффлайн-синтез
jarvis voice                    # скажите «Джарвис, ...»
jarvis panel                    # http://127.0.0.1:8787
```

Один вопрос без диалога:

```bash
jarvis ask "сколько места на диске"
```

## Режимы

| Команда | Что делает |
|---|---|
| `jarvis` / `jarvis chat` | диалог в терминале |
| `jarvis voice` | слушает микрофон, ждёт слово-активатор, отвечает вслух |
| `jarvis panel` | веб-панель: диалог, задачи, навыки, граф знаний, аналитика |
| `jarvis ask "..."` | одна реплика и выход — удобно вешать на горячую клавишу |
| `jarvis doctor` | проверка окружения: ключ, синтез, распознавание, микрофон |

Служебные команды прямо в диалоге: `/помощь`, `/память`, `/напоминания`,
`/задачи`, `/сброс`, `/выход`.

## Как это устроено

```
микрофон ──► faster-whisper ──► слово-активатор ──┐
                                                  ▼
клавиатура / веб-панель ───────────────────► Agent.ask()
                                                  │
                        системный промпт = персона + память + обстановка
                                                  │
                                    client.beta.messages.tool_runner
                                                  │
                            ┌─────────────────────┴─────────────────────┐
                            ▼                                           ▼
                   локальные инструменты                     серверный web_search
              (shell, файлы, память, задачи)                (на стороне Anthropic)
                            │
                            ▼
                    ответ ──► синтез речи ──► колонки
```

Несколько решений, которые стоит знать, если будете править код:

- **Агентный цикл не написан руками.** Его ведёт `tool_runner` из SDK — мы лишь
  зеркалим сообщения к себе, потому что ранер не отдаёт свою историю наружу
  (`jarvis/agent.py`). Зеркало нужно и для диска, и для перезапуска после `pause_turn`.
- **Системный промпт разбит на три блока** — от самого стабильного к самому
  изменчивому: персона (кэшируется), факты памяти, текущая обстановка. Кэш
  промптов префиксный, поэтому время суток лежит последним, а не первым.
- **Порядок инструментов зафиксирован** в `build_tools()` по той же причине.
- **История обрезается по границам ходов.** Срез не должен начинаться с
  `tool_result`, иначе API отвергнет запрос (`History.trim`).
- **На диск история кладётся простым JSON.** Блоки ответа модели — объекты SDK,
  их разворачивает `to_plain()`; без этого ассистент терял память при перезапуске.

## Навыки

Всё, что Джарвис умеет делать руками:

| Навык | Что делает | Подтверждение |
|---|---|---|
| `current_time`, `system_info` | время, ОС, рабочий каталог | нет |
| `list_dir`, `read_file` | смотрит файлы в рабочем каталоге | нет |
| `write_file` | пишет файл | **да** |
| `run_shell` | выполняет команду оболочки | **да**, кроме белого списка |
| `open_url`, `notify` | открывает ссылку, шлёт уведомление | `open_url` — **да** |
| `spawn_task`, `list_tasks`, `task_result`, `cancel_task` | фоновые исполнители | нет |
| `remember_fact`, `recall_facts`, `forget_fact` | долговременная память | нет |
| `add_reminder`, `list_reminders`, `cancel_reminder` | напоминания вслух | нет |
| `web_search` | поиск в интернете (серверный инструмент Anthropic) | нет |

### Несколько дел одновременно

Синхронный ассистент бесполезен ровно тогда, когда нужен больше всего: пока он
выполняет долгую команду, он молчит и не слышит. Поэтому долгая работа уходит
из диалога фоновым исполнителям.

```
👤 Джарвис, проверь диски и обнови зависимости

    основной диалог ──spawn_task──► [c46601] диски          ─┐
                    └─spawn_task──► [ac07bf] зависимости    ─┤ идут параллельно
                                                             │
🤖 Взялся за оба дела, доложу.        (0.16 с — диалог свободен)
                                                             │
🤖 Задача «диски» готова. Отчёт: всё чисто.   ◄──────────────┘
🤖 Задача «зависимости» готова. Отчёт: всё чисто.
```

Исполнитель — тот же агент, но:

- **со своей историей** (`~/.local/state/jarvis/tasks/<id>.json`) — контекст
  основного разговора он не засоряет и не читает, поэтому задачу ему надо
  формулировать целиком;
- **с общей памятью** — что узнал один, знают все (`Memory` под блокировкой,
  писателей несколько);
- **без права плодить исполнителей** — иначе одна просьба развернулась бы в
  лавину; `spawn_task` есть только у основного диалога;
- **но спрашивает разрешение так же, как диалог** — запрос доходит до вас,
  где бы вы ни были: в консоли, у микрофона или в панели (см. ниже).

Одновременно работают `max_parallel_tasks` штук (по умолчанию 3), остальные
ждут очереди. Остановка (`cancel_task`, кнопка «стоп» в панели) кооперативная:
исполнитель проверяет флаг на границе хода, чтобы не бросить начатый вызов
инструмента на полпути.

В терминале состояние показывает `/задачи`, в панели — раздел «Исполнители»
со схемой: кто сейчас работает и сколько времени.

### Добавить свой навык

Навык — это функция с докстрингом. Схему для модели SDK соберёт сам:

```python
# jarvis/tools/music.py
from anthropic import beta_tool
from .context import ToolContext

def register(ctx: ToolContext) -> list:
    @beta_tool
    def play_music(query: str) -> str:
        """Включает музыку по запросу.

        Args:
            query: Исполнитель, трек или настроение.
        """
        ctx.ensure_allowed(f"включить музыку: {query}")
        ...
        return f"играет {query}"

    return [play_music]
```

Останется добавить `tools += music.register(ctx)` в `jarvis/tools/__init__.py`.
Новый навык сразу появится и в диалоге, и в разделе «Навыки» панели.

## События: второй вход

У помощника два входа. Первый — вы заговорили. Второй, и он важнее, — **мир
изменился**: наступило напоминание, закончилась задача, пришло письмо.

Всё это одна сущность — событие, и обрабатывается одним циклом. Джарвис решает
одно из четырёх: **промолчать**, **запомнить**, **сделать**, **сказать**.

**Правила решают первыми, модель — в последнюю очередь.** Это решение про
приватность, а не про деньги: событие, разобранное правилом, никогда не
покидает машину. Человек обратился — отвечаем всегда. Напоминание — говорим
всегда. Ниже порога, ночью, из служебного каталога — молчим. Спорное уходит
модели, и то не чаще, чем позволяет бюджет.

**Порог вмешательства** (`speak_threshold`) и **часы тишины** (`quiet_from`,
`quiet_to`) — потому что помощник, который дёргает по любому поводу,
выключается через день.

**Очередь лежит на диске** — перезапуск ничего не теряет. Сбой возвращает
событие в очередь, но не больше трёх раз.

**Хроника живёт ограниченный срок** (`chronicle_days`, по умолчанию 30 дней).
Журнал происходящего без срока за год превращается в досье.

**Видно, что уходило наружу.** У каждого события помечено, разобрано оно на
месте или показывалось модели.

## Память

Память — не свалка фраз, а список того, что верно **сейчас**.

**Новое отменяет старое, а не ложится рядом.** Сказали «релизы теперь по
вторникам» — прежний факт про четверги помечается заменённым: в работу не
идёт, в модель не отправляется. Но и не исчезает: в панели видно, что чем
вытеснено. Молчаливое удаление ошибку скрыло бы, а так её заметно.

**Дубликаты не плодятся.** Повторили то же самое другими знаками препинания —
Джарвис узнает и не станет записывать второй раз.

**Важное помечено.** Аллергия и пароли — не то же самое, что кофе без сахара.
Важные факты выделены и для вас, и для модели.

**Видно, что пригождается.** У каждого факта счётчик обращений: сразу понятно,
что Джарвис правда использует, а что лежит мёртвым грузом.

**Поиск понимает склонения.** Записано «место работы» — спросите «где я
работаю», найдётся. Сравниваются основы слов, а не буквы, служебные слова
отбрасываются, а ответ отсортирован: сначала то, где совпало больше.
Морфология своя, без внешних словарей — `jarvis/morph.py`.

**Противоречие не проскочит молча.** Записывая факт, похожий на уже
известный, Джарвис получает предупреждение с идентификатором старого — и
может исправиться, указав, что именно отменяет. Раньше он мог просто не
заметить.

**Видно, откуда факт.** У каждого записано, узнан он в разговоре или
принесён фоновым исполнителем.

Старые файлы памяти читаются как есть — недостающие поля добираются
значениями по умолчанию.

## Приватность

Джарвис знает о владельце много, и это знание управляется так же просто,
как накапливается.

**Где лежит.** Всё личное — в `~/.local/state/jarvis/`: память, переписка,
напоминания, истории фоновых задач. Это **вне репозитория**: git этих файлов
не видит и на GitHub они попасть не могут.

**Кто может прочитать.** Только владелец: каталог `700`, файлы `600`.
Другой пользователь машины не прочитает ничего.

**Стереть.**

```bash
jarvis wipe                 # всё: переписка, память, задачи, напоминания
jarvis wipe --history       # только переписку
```

То же есть в диалоге командой `/стереть` и в панели, раздел «Приватность».
Файлы удаляются целиком, а не опустошаются: пустой список внутри оставил бы
прежние байты на диске до перезаписи.

**Не запоминать вовсе.**

```bash
jarvis --private
```

Разговор идёт как обычно, но на диск не пишется ничего — ни переписка, ни
новые факты. Прошлое с диска при этом не поднимается. После выхода не
остаётся следов.

**Что всё равно уходит наружу.** При каждой реплике в Claude API уезжают
память, последние сообщения переписки и результаты вызванных инструментов —
без этого модель не помнит, о чём был разговор. Звук с микрофона не уходит:
распознавание и синтез речи работают на машине владельца.

## Разрешения: доступ выдаёте вы

Ассистент с доступом к оболочке — это тот же терминал, только слушается голоса.
Поэтому доступ ко всему опасному Джарвис получает не по умолчанию, а от вас,
каждый раз.

Очередь запросов одна на всю систему (`jarvis/approvals.py`). Спросить может кто
угодно и откуда угодно — основной диалог, любой фоновый исполнитель, обработчик
запроса панели. Ответить можете вы, где вам удобно:

```
🤖 …работает над репликой
⚠️  Диалог просит разрешение: перезаписать файл ~/work/план.txt (11 символов)
   Разрешить? [да/нет]
👤 да
   разрешено
```

Чтобы это стало возможно в терминале, ход диалога выполняется **не в главном
потоке**. Главный поток — консоль оператора: он свободен, чтобы задать вопрос и
принять ответ, пока диалог ждёт. Иначе разрешение, которое запросил сам диалог,
было бы некому выдать — ввод занят им же.

Мелочи, которые видно только на практике:

- **голосом** — запрос произносится вслух, ответ «да»/«нет» принимается без
  слова-активатора: он только что спросил, звать его по имени незачем;
- **реплика, сказанная раньше запроса, не теряется** — она подождёт в буфере,
  пока появится тот, кто её примет;
- **выход не обрывает начатое** — `/выход` и Ctrl+D дожидаются, пока
  завершится ход и разойдутся висящие запросы;
- **отказ — это обычный результат**, а не сбой: модель получает текст «владелец
  отклонил действие», без трассировок в консоли;
- **таймаут `approval_timeout`** (5 минут) — не политика, а страховка на случай
  пустого кресла: если никто не ответил, действие не выполняется.

Остальное:

- `confirm_mode` / `task_confirm_mode`: `ask` (по умолчанию), `auto` — без
  вопросов, `deny` — режим «только чтение»;
- белый список `shell_allowlist` — команды, которые не требуют вопроса
  (`ls`, `git status` и подобные);
- файловые инструменты не выходят за `workspace` — путь вне корня отклоняется
  до любых операций;
- панель слушает `127.0.0.1` — снаружи к ней не подключиться;
- вход в панель по токену: он лежит в `~/.local/state/jarvis/panel-token`,
  доступен только владельцу и не меняется при перезапуске.

## Настройка

Приоритет: значения по умолчанию → `~/.config/jarvis/config.toml` →
переменные `JARVIS_*` → флаги командной строки.

```toml
# ~/.config/jarvis/config.toml
model = "claude-opus-5"
effort = "medium"           # low | medium | high | xhigh | max
confirm_mode = "ask"        # ask | auto | deny
workspace = "~/projects"
web_search = true

approval_timeout = 300      # сколько секунд запрос ждёт вашего ответа
max_parallel_tasks = 3      # сколько фоновых исполнителей работает разом
task_effort = "high"        # они работают без присмотра — думать им стоит глубже
task_confirm_mode = "ask"   # ask | auto | deny

wake_word = "джарвис"
stt_model = "small"         # tiny | base | small | medium | large-v3
tts_backend = "auto"        # auto | piper | say | espeak | pyttsx3 | none
shell_allowlist = ["ls", "cat", "git status", "git log"]
```

То же самое через окружение: `JARVIS_EFFORT=high`, `JARVIS_CONFIRM_MODE=auto`,
`JARVIS_WORKSPACE=~/projects`.

Состояние (память, напоминания, история) лежит в
`~/.local/state/jarvis/` — обычный JSON, его можно читать и править руками.

## Всегда под рукой

Голос, постоянное присутствие и понимание с полуслова упираются в одно:
Джарвис должен работать всегда, а не только пока открыт терминал.

```bash
ANTHROPIC_API_KEY=sk-ant-... deploy/install.sh
```

Ставит службу: автозапуск после перезагрузки, перезапуск при падении.
Linux — systemd, macOS — launchd, Windows — Планировщик заданий вручную
(подсказку скрипт напечатает).

Панель при этом слушает **только 127.0.0.1**. Открыть её остальной локальной
сети можно флагом `--lan`, но тогда её увидит каждый в том же вайфае —
защищать будет только токен. По умолчанию наружу не смотрит ничего.

## Работа над проектом

Правила для Claude Code лежат в `CLAUDE.md`, настройки — в `.claude/`:

- `hooks/session-start.sh` — ставит зависимости при старте облачной сессии,
  чтобы тесты и линтер работали сразу;
- `settings.json` — регистрирует хук и разрешает рутинные команды
  (тесты, линтер, git) без лишних вопросов;
- `commands/` — команды быстрого доступа: `/check` (линтер и тесты),
  `/wrap` (проверить, закоммитить, запушить), `/skill` (добавить навык).

## Тесты

```bash
pip install -e '.[dev]'
pytest                      # 36 тестов, ~6 с
ruff check jarvis/ tests/   # линтер
```

Тесты не требуют ни ключа API, ни микрофона: агент прогоняется против локальной
заглушки Messages API, которая проверяет и форму запроса, и цикл вызова
инструментов.

## Что дальше

Очевидные следующие шаги, если захочется довести до «operator OS»:

- горячая клавиша вместо слова-активатора (`jarvis ask` уже готов к этому);
- потоковый ответ и синтез по предложениям — чтобы Джарвис начинал говорить,
  не дожидаясь конца мысли;
- подключение почты, календаря и мессенджеров через MCP-серверы;
- роли для исполнителей вместо одной общей персоны и доска задач между ними;
- серверная компактация истории для по-настоящему длинных разговоров.
