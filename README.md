# JARVIS

Личный ассистент на Claude API: голос, инструменты, долговременная память,
напоминания и локальная панель оператора.

Репозиторий отвечает на вопрос «как превратить Claude в Джарвиса» не текстом,
а работающим кодом.

---

## Чего не хватает языковой модели, чтобы стать Джарвисом

Сама по себе модель — это «отвечает на вопросы». Джарвис — это «слышит, делает,
помнит и не забывает напомнить». Разница складывается из четырёх слоёв, и все
четыре есть в этом репозитории:

| Слой | Что даёт | Где в коде |
|---|---|---|
| **Голос** | слушает микрофон, реагирует на имя, отвечает вслух | `jarvis/voice/` |
| **Руки** | выполняет команды, читает и пишет файлы, ищет в вебе | `jarvis/tools/` |
| **Память** | помнит владельца между запусками, а не только внутри чата | `jarvis/memory.py` |
| **Инициатива** | сам подаёт голос, когда наступил срок | `jarvis/reminders.py` |

Плюс два слоя, без которых это опасная игрушка, а не ассистент:

- **Разрешения** — опасные действия требуют подтверждения (`jarvis/tools/context.py`);
- **Панель оператора** — видно, что он помнит, что умеет и куда уходят токены
  (`jarvis/dashboard/`).

## Быстрый старт

```bash
git clone https://github.com/Kop001/Restart-.git
cd Restart-
pip install -e .

export ANTHROPIC_API_KEY=sk-ant-...   # или `ant auth login`

jarvis doctor      # что доступно, а что нет
jarvis             # диалог в терминале
```

Голос и панель:

```bash
pip install -e '.[voice,tts]'   # микрофон + faster-whisper + оффлайн-синтез
jarvis voice                    # скажите «Джарвис, ...»
jarvis panel                    # http://127.0.0.1:8787
```

Один вопрос без диалога:

```bash
jarvis ask "сколько места на диске"
```

## Режимы

| Команда | Что делает |
|---|---|
| `jarvis` / `jarvis chat` | диалог в терминале |
| `jarvis voice` | слушает микрофон, ждёт слово-активатор, отвечает вслух |
| `jarvis panel` | веб-панель: диалог, задачи, навыки, граф знаний, аналитика |
| `jarvis ask "..."` | одна реплика и выход — удобно вешать на горячую клавишу |
| `jarvis doctor` | проверка окружения: ключ, синтез, распознавание, микрофон |

Служебные команды прямо в диалоге: `/помощь`, `/память`, `/напоминания`,
`/сброс`, `/выход`.

## Как это устроено

```
микрофон ──► faster-whisper ──► слово-активатор ──┐
                                                  ▼
клавиатура / веб-панель ───────────────────► Agent.ask()
                                                  │
                        системный промпт = персона + память + обстановка
                                                  │
                                    client.beta.messages.tool_runner
                                                  │
                            ┌─────────────────────┴─────────────────────┐
                            ▼                                           ▼
                   локальные инструменты                     серверный web_search
              (shell, файлы, память, задачи)                (на стороне Anthropic)
                            │
                            ▼
                    ответ ──► синтез речи ──► колонки
```

Несколько решений, которые стоит знать, если будете править код:

- **Агентный цикл не написан руками.** Его ведёт `tool_runner` из SDK — мы лишь
  зеркалим сообщения к себе, потому что ранер не отдаёт свою историю наружу
  (`jarvis/agent.py`). Зеркало нужно и для диска, и для перезапуска после `pause_turn`.
- **Системный промпт разбит на три блока** — от самого стабильного к самому
  изменчивому: персона (кэшируется), факты памяти, текущая обстановка. Кэш
  промптов префиксный, поэтому время суток лежит последним, а не первым.
- **Порядок инструментов зафиксирован** в `build_tools()` по той же причине.
- **История обрезается по границам ходов.** Срез не должен начинаться с
  `tool_result`, иначе API отвергнет запрос (`History.trim`).
- **На диск история кладётся простым JSON.** Блоки ответа модели — объекты SDK,
  их разворачивает `to_plain()`; без этого ассистент терял память при перезапуске.

## Навыки

Всё, что Джарвис умеет делать руками:

| Навык | Что делает | Подтверждение |
|---|---|---|
| `current_time`, `system_info` | время, ОС, рабочий каталог | нет |
| `list_dir`, `read_file` | смотрит файлы в рабочем каталоге | нет |
| `write_file` | пишет файл | **да** |
| `run_shell` | выполняет команду оболочки | **да**, кроме белого списка |
| `open_url`, `notify` | открывает ссылку, шлёт уведомление | `open_url` — **да** |
| `remember_fact`, `recall_facts`, `forget_fact` | долговременная память | нет |
| `add_reminder`, `list_reminders`, `cancel_reminder` | напоминания вслух | нет |
| `web_search` | поиск в интернете (серверный инструмент Anthropic) | нет |

### Добавить свой навык

Навык — это функция с докстрингом. Схему для модели SDK соберёт сам:

```python
# jarvis/tools/music.py
from anthropic import beta_tool
from .context import ToolContext

def register(ctx: ToolContext) -> list:
    @beta_tool
    def play_music(query: str) -> str:
        """Включает музыку по запросу.

        Args:
            query: Исполнитель, трек или настроение.
        """
        ctx.ensure_allowed(f"включить музыку: {query}")
        ...
        return f"играет {query}"

    return [play_music]
```

Останется добавить `tools += music.register(ctx)` в `jarvis/tools/__init__.py`.
Новый навык сразу появится и в диалоге, и в разделе «Навыки» панели.

## Безопасность

Ассистент с доступом к оболочке — это тот же терминал, только слушается голоса.
Поэтому:

- `confirm_mode = "ask"` (по умолчанию) — запись файлов, команды вне белого
  списка и открытие ссылок требуют явного «да»: в терминале вопросом, в панели
  модальным окном;
- `confirm_mode = "auto"` — без вопросов. Включайте, только понимая, что делаете;
- `confirm_mode = "deny"` — режим «только чтение»;
- файловые инструменты не выходят за `workspace` — путь вне корня отклоняется
  до любых операций;
- панель слушает `127.0.0.1` и не имеет авторизации: не выставляйте её наружу.

## Настройка

Приоритет: значения по умолчанию → `~/.config/jarvis/config.toml` →
переменные `JARVIS_*` → флаги командной строки.

```toml
# ~/.config/jarvis/config.toml
model = "claude-opus-5"
effort = "medium"           # low | medium | high | xhigh | max
confirm_mode = "ask"        # ask | auto | deny
workspace = "~/projects"
web_search = true

wake_word = "джарвис"
stt_model = "small"         # tiny | base | small | medium | large-v3
tts_backend = "auto"        # auto | piper | say | espeak | pyttsx3 | none
shell_allowlist = ["ls", "cat", "git status", "git log"]
```

То же самое через окружение: `JARVIS_EFFORT=high`, `JARVIS_CONFIRM_MODE=auto`,
`JARVIS_WORKSPACE=~/projects`.

Состояние (память, напоминания, история) лежит в
`~/.local/state/jarvis/` — обычный JSON, его можно читать и править руками.

## Тесты

```bash
pip install -e '.[dev]'
pytest
```

Тесты не требуют ни ключа API, ни микрофона: агент прогоняется против локальной
заглушки Messages API, которая проверяет и форму запроса, и цикл вызова
инструментов.

## Что дальше

Очевидные следующие шаги, если захочется довести до «operator OS»:

- горячая клавиша вместо слова-активатора (`jarvis ask` уже готов к этому);
- потоковый ответ и синтез по предложениям — чтобы Джарвис начинал говорить,
  не дожидаясь конца мысли;
- подключение почты, календаря и мессенджеров через MCP-серверы;
- субагенты под отдельные роли и общая доска задач между ними;
- серверная компактация истории для по-настоящему длинных разговоров.
